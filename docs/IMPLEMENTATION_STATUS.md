- PDF 양옆 페이지 버튼, 마우스·키보드로 조절하고 브라우저에 저장하는 학습 도우미 너비.

- 내장 북마크 우선, 없으면 앞부분 목차 페이지의 텍스트·로컬 OCR 추출. 다단·연속 페이지, 그림·표 목록과 숫자 표 제외, 하단 쪽수 기반 PDF 오프셋 확인, 수동 보정과 브라우저 저장, 서버 캐시.

## 실제 API 연결 검증

아래 실제 호출 기록은 2026-10-29의 이전 키에 대한 결과다. 이후 교체된 키의 검증은 사용자 요청에 따라 미뤘으며 2026-10-30 개선 작업에서 호출하지 않았다.

기존 `.env`의 API 키 값은 출력·변경하지 않았다. 모델 미설정을 보완해 `LLM_MODEL=gpt-5.4-mini`를 추가했다. 최초 인증 오류는 상속된 셸 API 키가 프로젝트 키를 가렸기 때문이었다. 프로젝트 `.env` 키를 우선하도록 수정하고 회귀 테스트를 추가했다. 실제 프로젝트 키로 인증·모델 접근이 정상임을 확인했다.

`scripts/verify_live.py`로 임시 SQLite와 직접 생성한 PDF를 사용해 전체 업로드→컨텍스트→실제 모델 스트리밍→DB 저장 경로를 검증했다. 텍스트 PDF는 입력 188 / 출력 29토큰, 이미지 전용 스캔 PDF는 입력 2,595 / 출력 23토큰으로 모두 completed 상태를 저장했다. 스캔 페이지의 이미지 첨부도 확인했다. 이 결과는 합성 문서의 연결 검증이며 실제 전문서적의 답변 품질 평가는 별도로 남는다. 기본 테스트는 유료 API를 호출하지 않으며 `make test-live`만 실제 API를 사용한다.

## 초기 설계 대비 조정과 후속 작업

- 초기 규모에 맞게 `app/main.py`에 API·서비스 조립을 모았다. PDF·설정·DB·모델·스키마·LLM 경계는 별도 모듈이며, API 모듈 세분화는 기능 규모가 커질 때 수행한다.
- 모델 메뉴는 서버 환경변수의 허용 목록으로 구성하고 사용자의 선택은 DB에 저장한다. 모델별 실제 계정 접근 권한 조회와 다른 공급자 지원은 후속 작업이다.
- PyMuPDF는 OCR·레이아웃 모델의 추가 의존성을 피하기 위해 1.x 계열로 제한했다. 잠금 파일이 실제 설치 버전을 고정한다.
- 선택 문구를 별도 문맥으로 보존하고 긴 페이지 본문은 앞부분부터 예산에 맞춰 자른다. 선택 위치 중심의 주변 문단 추출은 후속 개선이다.
- 실제 물리 기기 간 LAN 접속, 운영 프록시·백업 복원, 회전·다단 편집·수식이 많은 실제 책의 품질과 대형 PDF 성능은 별도 검증이 남아 있다.
- 본문 전체 OCR, RAG, 사용자 북마크·주석, Import/Export, 인증·인터넷 공개, 동시 편집 충돌 해결은 구현하지 않았다. 목차 페이지에 한정한 한국어·영어 OCR은 지원한다.

핵심 MVP 흐름과 실제 AI 통합은 동작을 확인했다. 실제 Mac mini·물리 기기의 LAN 운영 검수와 전문서적 품질·성능 검증을 마친 뒤 운영 완료를 판단한다.

2026-10-30 연속 목차 누락 수정: 쪽 번호를 포함한 Contents 머리말 인식, 손상된 기존 OCR 텍스트층의 숫자 열 재인식과 점선 제거, 빠진 장 제목 복원, 경계 쪽수 오류가 다음 목차 전체를 탈락시키는 문제 수정, 추출 규칙 버전에 따른 캐시 자동 갱신. 백엔드 **56개**, 프론트엔드 **4개**, Ruff·TypeScript·운영 빌드 통과. 사용자 도서에서 상세 목차의 마지막 색인까지 추출되는 것을 로컬 검증했다. 테스트에는 사용자 문서를 포함하지 않고 합성 문서로 회귀 조건을 재현했다.


## 2026-10-31 PDF 내부 참조 링크

- 내부 링크 클릭·Enter로 독립 참조 미리보기, 미리보기 확대·스크롤, 본문 목적지 이동, PDF 영역 위쪽의 참조 복귀 버튼을 구현했다. 본문과 미리보기는 하나의 PDF 문서를 공유하며, 미리보기 조작은 독서 상태 저장·AI 질문 문맥에 연결하지 않는다.
- 명명/명시 목적지와 페이지 참조/정수 인덱스를 해석하고 viewport 변환으로 회전·crop을 반영한다. 같은 페이지 내 좌표 이동, null 좌표 보존, 잘못된 목적지의 오류 안내와 지원하지 않는 좌표 형식의 페이지 보기 대체를 지원한다. 본문 이동 시 현재 줌을 유지한다.
- PDF 좌표 기준으로 가로세로 위치와 줌을 캡처해 최대 50개 세션 이력에서 역순 복귀한다. 렌더링 실패 시 원위치로 복구하고 이력에는 실패 이동을 추가하지 않는다. 빠른 참조 변경 시 이전 결과를 무시하고 미리보기 닫기·책 전환 시 렌더 작업을 취소한다.
- 데스크톱은 드래그·크기 조절 가능한 비모달 창이며 가능한 경우 링크 문장을 피해서 연다. 모바일은 높이 슬라이더가 있는 하단 시트다. Escape·닫기 시 원래 링크 또는 본문으로 포커스를 복원한다. 허용된 외부 웹 URL은 새 탭으로 연다.
- 설계의 범용 AnnotationLayer 대신 Link 주석만 별도 HTML 영역으로 표시했다. 기존 canvas·텍스트층과 현재 React 뷰어를 유지하기 위한 선택이다. 서버·DB·패키지 의존성은 변경하지 않았다. 상세 구조와 한계는 [참조 링크 설계·구현 기록](PDF_REFERENCE_LINKS.md)에 정리했다.
- 검증: Ruff·백엔드 **56개**, 프론트엔드 **9개**, TypeScript·운영 빌드 통과. 전체 Chrome 통합 **8개** 통과 후, 창 초기 위치와 null 좌표 보존 보완분은 참조 통합 **2개**를 다시 실행해 통과했다. 저장 상태 테스트의 기존 모호한 status 선택자를 저장 상태 영역으로 한정했다.
- 참조 테스트는 직접 생성한 PDF와 별도 포트·격리된 fake 서재를 사용했다. 미리보기 중 본문/서버 상태 유지, 손상된 명명 목적지, 외부 링크 속성, 같은 페이지 이동, A→B→C 복귀, 가로세로·줌 복원, 강제로 유발한 canvas 렌더 실패의 원위치 복구, 키보드 포커스, 텍스트 선택과 모바일 시트를 확인했다. 데스크톱·모바일 화면 캡처도 확인했다. 외부 AI는 호출하지 않았다.
- 그림 경계 자동 추출, 링크 없는 참조 문구의 자동 링크 생성, 미리보기 내 중첩 링크, 새로고침·다른 기기로 이어지는 참조 이력은 후속 범위다. 실제 사용자 교재의 목적지 품질과 대형 문서 성능은 별도 검증이 필요하다.
