# 구현·검증 현황

기준일: 2026-10-30

## 구현된 기능

- React·TypeScript·Vite 프론트엔드와 FastAPI 백엔드, uv/npm 잠금 파일과 설치·실행 명령.
- SQLAlchemy·Alembic 초기 마이그레이션, SQLite WAL/FK, 서버 재시작 시 중단 요청 복구.
- UUID 파일 저장, 스트리밍 업로드 크기 제한, PDF 파싱·암호화·페이지 수 검증, 별도 프로세스의 PDF 처리·시간 제한.
- 라이브러리와 명시적 삭제 확인, 삭제 실패 재시도, 대화·독서 상태 cascade 삭제.
- PDF.js canvas/text layer, 텍스트 선택, 페이지·줌·세로 스크롤 저장과 복원, 순차 저장 큐와 실패 재시도.
- 책별 대화·문맥 스냅샷, POST SSE, heartbeat, 부분 응답 저장, 중복 호출 방지, 실패·중단 요청의 명시적 재시도.
- OpenAI Responses SDK 어댑터, 실제 AI와 구분되는 fake 어댑터, 입력 예산 제한·최근 완료 대화·이미지 모드.
- 스캔 페이지의 서버 이미지 렌더링·캐시, 이미지 입력 지원 설정, 전송 범위 UI 안내.
- 같은 서버에 접속한 별도 브라우저 세션의 위치·이력 복원, 운영 빌드의 동일 origin 제공.
- PDF 양옆 페이지 버튼, 마우스·키보드로 조절하고 브라우저에 저장하는 학습 도우미 너비.
- 설명 모델 선택·서버 저장·요청별 모델 고정, 기존 설정을 보존하는 0002 마이그레이션.
- KaTeX 수식 조판과 Mermaid 다이어그램, LaTeX 구분자 호환·잘못된 입력의 원문 표시.

## 검증 기록

- 백엔드 통합 테스트: 도서 등록·Range·삭제, 127쪽 상태의 서버 재시작 복원, 손상/암호화/크기/페이지 수 제한, 스캔 이미지, 책별 격리, 중복 요청, 부분 답변·재시도, 서버 중단 복구, 설정 오류, origin/host 검증, timeout, 이력 페이지네이션.
- 실제 OpenAI Python SDK + HTTP 모의 전송으로 요청 스키마, 이미지 입력, `store=false`, 스트리밍 이벤트 변환과 usage 보존 검증.
- 프론트엔드 SSE 파서: 한글 UTF-8 바이트·CRLF·이벤트 경계 분할, 미완성 프레임 종료.
- Chrome 브라우저 테스트와 화면 캡처로 독서·질문·복원·삭제·모바일 흐름 검수.
- TypeScript 검사·운영 빌드, Ruff 검사, npm 의존성 audit, Git 개인 데이터 제외 확인.

이전 MVP 검증(2026-10-29): 백엔드 **16개**, SSE 파서 **2개**, Chrome 통합 **3개** 통과. TypeScript·운영 빌드·Ruff 검사와 운영 SPA·정적 자산·PDF 폰트 제공을 확인했다. PyMuPDF SWIG 타입의 DeprecationWarning은 테스트 실패 없이 남아 있다.

2026-10-30 개선 검증: 백엔드 **19개**, 프론트엔드 **4개** 통과. 모델 선택 저장·SDK 요청 전달·재시도 모델 고정·기존 DB 설정 보존을 검증했다. Chrome에서 양옆 페이지 버튼, 모델 선택 복원, 마우스·키보드 너비 조절·복원, 수식·한글 다이어그램과 잘못된 다이어그램의 대체 표시를 확인했다. 이번 검증은 별도 포트·테스트 서재와 fake 어댑터를 사용하며 새 API 키를 호출하지 않는다.

최종 Chrome 통합 **4개**, TypeScript·운영 빌드·Ruff 검사 통과. npm audit 보고 취약점 **0개**. 일부 Mermaid 다이어그램 엔진의 지연 로딩 청크는 Vite의 500kB 권장치를 초과하며 빌드는 정상 완료된다. 모델 선택 기능은 서버 재시작 시 0002 마이그레이션이 적용된 뒤 사용할 수 있다.

## 실제 API 연결 검증

아래 실제 호출 기록은 2026-10-29의 이전 키에 대한 결과다. 이후 교체된 키의 검증은 사용자 요청에 따라 미뤘으며 2026-10-30 개선 작업에서 호출하지 않았다.

기존 `.env`의 API 키 값은 출력·변경하지 않았다. 모델 미설정을 보완해 `LLM_MODEL=gpt-5.4-mini`를 추가했다. 최초 인증 오류는 상속된 셸 API 키가 프로젝트 키를 가렸기 때문이었다. 프로젝트 `.env` 키를 우선하도록 수정하고 회귀 테스트를 추가했다. 실제 프로젝트 키로 인증·모델 접근이 정상임을 확인했다.

`scripts/verify_live.py`로 임시 SQLite와 직접 생성한 PDF를 사용해 전체 업로드→컨텍스트→실제 모델 스트리밍→DB 저장 경로를 검증했다. 텍스트 PDF는 입력 188 / 출력 29토큰, 이미지 전용 스캔 PDF는 입력 2,595 / 출력 23토큰으로 모두 completed 상태를 저장했다. 스캔 페이지의 이미지 첨부도 확인했다. 이 결과는 합성 문서의 연결 검증이며 실제 전문서적의 답변 품질 평가는 별도로 남는다. 기본 테스트는 유료 API를 호출하지 않으며 `make test-live`만 실제 API를 사용한다.

## 초기 설계 대비 조정과 후속 작업

- 초기 규모에 맞게 `app/main.py`에 API·서비스 조립을 모았다. PDF·설정·DB·모델·스키마·LLM 경계는 별도 모듈이며, API 모듈 세분화는 기능 규모가 커질 때 수행한다.
- 모델 메뉴는 서버 환경변수의 허용 목록으로 구성하고 사용자의 선택은 DB에 저장한다. 모델별 실제 계정 접근 권한 조회와 다른 공급자 지원은 후속 작업이다.
- PyMuPDF는 OCR·레이아웃 모델의 추가 의존성을 피하기 위해 1.x 계열로 제한했다. 잠금 파일이 실제 설치 버전을 고정한다.
- 선택 문구를 별도 문맥으로 보존하고 긴 페이지 본문은 앞부분부터 예산에 맞춰 자른다. 선택 위치 중심의 주변 문단 추출은 후속 개선이다.
- 실제 물리 기기 간 LAN 접속, 운영 프록시·백업 복원, 회전·다단 편집·수식이 많은 실제 책의 품질과 대형 PDF 성능은 별도 검증이 남아 있다.
- OCR, RAG, 북마크·주석, Import/Export, 인증·인터넷 공개, 동시 편집 충돌 해결은 구현하지 않았다.

핵심 MVP 흐름과 실제 AI 통합은 동작을 확인했다. 실제 Mac mini·물리 기기의 LAN 운영 검수와 전문서적 품질·성능 검증을 마친 뒤 운영 완료를 판단한다.
