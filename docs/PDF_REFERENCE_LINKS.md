# PDF 내부 참조 링크 개선안

작성일: 2026-10-31 · 상태: 기본 기능 구현 완료. 아래 설계와 구현 전 조사 기록을 보존하며 구현 결과는 다음 절에 기록한다.

## 구현 결과

- `PdfView.tsx`가 PDF 문서를 한 번 로딩하고 참조 미리보기·복귀 스택·이동 실패 복구를 관리한다. `PdfPage.tsx`는 공유 문서를 받아 독립 canvas·텍스트층·줌·스크롤·취소 가능한 렌더링을 관리한다. `pdfReferences.ts`에서 목적지 검증·좌표 변환·외부 URL 검증을 담당한다.
- 초기 제안의 범용 `AnnotationLayer`/링크 서비스 어댑터 대신, `getAnnotations()`의 Link 주석만 viewport 좌표로 변환해 HTML 링크 영역으로 표시했다. 현재 canvas 뷰어에 필요한 내부 목적지와 허용한 외부 URL만 연결하기 위한 구현 선택이다. PDF.js가 웹 URL로 제공하는 링크는 허용된 스킴일 때 새 탭으로 연다. 내부 목적지가 없는 로컬 파일 링크에는 안내를 표시하며, 다른 주석·폼·PDF 실행 동작은 연결하지 않는다. 주석 로딩 실패도 본문 렌더링을 막지 않는다.
- 클릭·Enter로 미리보기, 독립 확대·스크롤, 본문 이동, 최대 50개의 세션 복귀 이력, 같은 페이지 내 좌표 이동, 렌더 실패 시 원위치 복구를 구현했다. 가로 위치를 포함한 PDF 좌표로 복귀하며 줌 변경에도 페이지의 기준점을 유지한다. 빠른 참조 변경 시 이전 비동기 결과를 무시한다.
- 데스크톱 창은 드래그·크기 조절을 지원하고 링크 문장을 피할 수 있는 초기 위치를 선택한다. 독서 패널 크기가 바뀌면 창 위치를 영역 안으로 보정한다. 모바일은 높이 슬라이더가 있는 하단 시트다. 복귀 버튼은 기존 페이지 버튼과 구분해 PDF 영역 왼쪽 위에 표시한다.
- 본문만 기존 독서 상태 저장과 질문 문맥에 연결한다. 미리보기 닫기·Escape 시 링크 포커스를 복원한다. 원래 링크 DOM이 페이지 변경으로 사라졌으면 본문으로 포커스를 돌린다.
- 서버·DB·의존성 변경은 없다. 그림 자동 잘라내기, 링크 없는 문구 감지, 미리보기 중첩 링크, 세션을 넘는 복귀 이력은 후속 범위다.
- 직접 생성한 PDF를 사용한 Chrome 통합 테스트와 목적지 단위 테스트를 추가했다. 상세 검증 결과는 [구현·검증 현황](IMPLEMENTATION_STATUS.md)에 기록한다. 실제 사용자 교재의 도착 정확도와 대형 문서 성능은 별도 검증이 남는다.

## 권장 방향

내부 링크를 클릭하면 **앱 안의 참조 미리보기**를 열고, 미리보기의 **해당 위치로 이동**으로 본문 뷰어를 이동시키는 조합을 권장한다. 본문을 이동시킨 경우에는 **참조 이동 전으로 돌아가기**를 제공한다. 새 브라우저 창은 사용하지 않는다.

이 앱의 주요 작업은 교재를 읽으며 그림·수식과 설명을 대조하는 것이다. 미리보기는 읽던 문장과 AI 대화를 유지하면서 참조를 확인하는 데 적합하다. 참조 페이지에서 계속 읽거나 큰 그림을 확인하려는 경우에는 실제 이동을 사용한다. 다음 비교는 현재 화면 구성과 학습 목적에 따른 설계 판단이며, 사용자 실험 결과는 아니다.

| 기준 | 직접 이동 + 돌아가기 | 앱 안의 참조 미리보기 |
|---|---|---|
| 본문과 그림 대조 | 왕복이 필요함 | 함께 확인할 수 있음 |
| 큰 그림·주변 설명 탐색 | 기존 PDF 영역 전체를 사용 | 확대·스크롤 또는 본문 이동이 필요함 |
| 읽던 위치 유지 | 복귀 이력 구현이 필요함 | 본문 위치를 유지함 |
| 현재 코드 적용 | 링크 처리·좌표 이동·이력 추가 | 공통 링크 처리에 두 번째 렌더링 영역 추가 |
| 좁은 화면 | 공간 제약이 적음 | 미리보기가 본문을 가릴 수 있음 |

구현 순서는 직접 이동과 복귀를 먼저 완성하고 미리보기를 추가한다. 두 기능 모두 동일한 링크 해석·좌표 변환을 사용하므로 선행 작업을 재사용할 수 있다. 최종 기본 동작은 미리보기로 한다.

## 구현 전 프로젝트에서 확인한 사항

- `frontend/src/PdfView.tsx`: PDF.js의 `getDocument`, canvas, `TextLayer`로 한 페이지씩 표시한다. 링크 주석을 읽거나 클릭 영역을 표시하는 코드는 없다. `pdf_viewer.css`를 불러오는 것만으로 링크가 활성화되지는 않는다.
- `frontend/src/Reader.tsx`: `pageTo()`가 페이지를 바꾸고 세로 스크롤을 0으로 초기화한다. 목차도 이 함수를 사용한다. 페이지 내 목적지 좌표 처리와 참조 복귀 이력은 없다.
- `frontend/src/useReadingState.ts` 및 `api.ts`: `page`, `zoom`, 세로 스크롤 비율인 `scroll_offset`을 500ms 지연 저장한다. 현재 페이지 재개에 활용할 수 있지만 가로 스크롤과 PDF 좌표는 저장하지 않는다.
- `frontend/src/style.css`: PDF와 너비 조절 가능한 학습 도우미를 나란히 표시한다. 모바일은 세로 배치다. 세 번째 고정 패널은 기존 영역을 좁힐 가능성이 있다.
- 설치된 `pdfjs-dist` 4.10.38 타입과 번들에서 `getAnnotations()`, `getDestination()`, `getPageIndex()`, `AnnotationLayer`, viewport 좌표 변환 API를 확인했다.

내부 참조 처리는 기존 프론트엔드와 PDF.js로 구현 가능하다. 최초 범위에는 새 서버 API, DB 변경, OCR, 외부 AI 호출이 필요하지 않을 것으로 판단한다. 실제 교재 링크의 도착 정확도와 미리보기 성능은 구현 후 검증해야 한다.

## 사용자 동작

1. 본문의 내부 링크를 클릭하거나 키보드 Enter로 실행하면 참조 미리보기를 연다. 텍스트를 드래그해 선택하는 동작과 구분한다.
2. 넓은 화면에는 이동·크기 조절 가능한 비모달 창을 PDF 영역 위에 표시한다. 본문 스크롤과 학습 도우미를 계속 사용할 수 있게 하고, 처음에는 링크 문장이 보이는 위치를 최대한 피한다. 본문과 참조를 동시에 볼 공간이 부족하면 직접 이동을 제공한다.
3. 좁은 화면에는 높이 조절 가능한 하단 시트를 사용한다. 공간이 부족한 경우 동시 열람의 한계를 인정하고 직접 이동 버튼을 쉽게 접근할 수 있게 한다.
4. 미리보기에는 `참조 · PDF 83쪽`, 확대/축소, 해당 위치로 이동, 닫기를 표시한다. 링크 주변 텍스트를 확실히 얻을 수 있을 때만 `Figure 2.17b` 같은 제목을 덧붙인다.
5. 미리보기는 참조 페이지를 렌더링한 뒤 도착 좌표가 보이도록 스크롤한다. 주변 캡션과 설명도 확인할 수 있게 한다. 좌표가 없으면 페이지 전체를 맞춰 보여준다.
6. 미리보기 열기·스크롤·확대는 본문 독서 위치와 질문 문맥을 바꾸지 않는다. 참조 페이지를 AI 질문 대상으로 보내는 기능은 별도 범위다. 현재처럼 질문은 본문 페이지·선택 문구를 사용한다.
7. 해당 위치로 이동하면 미리보기를 닫고 본문을 목적지로 이동시킨다. 툴바의 참조 복귀 버튼으로 원래 페이지·줌·화면 위치를 복원한다. 기존 이전/다음 페이지 버튼과 구분한다.
8. 닫기와 Escape를 지원하고, 닫은 뒤 실행한 링크로 포커스를 돌린다. 이동 후에는 본문 도착 위치에 포커스를 제공한다. 데스크톱 비모달 창에는 포커스 가두기를 적용하지 않는다.

PDF 링크의 목적지는 페이지나 좌표일 수 있으며 그림 경계를 보장하지 않는다. 따라서 첫 버전은 그림 자동 잘라내기를 약속하지 않는다. `Figure 2.17b` 링크가 그림 전체 또는 페이지 상단을 가리키면 그 위치를 그대로 보여주며, 하위 그림 b만 별도로 추출하지 않는다.

## 구현 구조

### 링크 해석과 표시

- 공통 목적지 해석 모듈에서 내부 `GoTo` 링크의 명명 목적지와 명시적 목적지를 처리한다. 명명 목적지는 클릭할 때 `getDestination(name)`으로 해석하며 문서 전체 목적지 목록을 미리 읽지 않는다.
- 페이지 참조 객체는 `getPageIndex(ref) + 1`, 정수 페이지 인덱스도 검증 후 1 기반 페이지 번호로 변환한다. 실제 PDF 목적지에는 목차용 인쇄 쪽수 보정을 적용하지 않는다.
- 링크 영역은 PDF.js `AnnotationLayer`와 현재 React 뷰어를 잇는 링크 서비스 어댑터로 표시한다. `PDFLinkService`는 PDF 뷰어와의 연결을 전제로 하므로 import만으로 현재 canvas 뷰어에 연결되지는 않는다. 모든 내부 이동은 공통 콜백으로 미리보기 또는 본문 이동에 전달한다.
- 현재 viewport로 링크 사각형을 변환해 줌·회전·페이지 crop에 맞춘다. 텍스트 선택을 방해하지 않는지 검증한다. 처리하지 않는 링크는 성공한 것처럼 이동시키지 않는다.
- 초기 목적지 범위는 `XYZ`, `Fit`, `FitB`, `FitH`, `FitBH`, `FitV`, `FitBV`, `FitR`로 명시하고 각각의 null 좌표·맞춤 의미를 처리한다. 본문 이동은 현재 줌을 유지하는 정책을 사용하고, 미리보기는 창에 맞춘 배율로 시작한다. 처리 불가능한 형식은 안내 후 페이지 전체 보기로 전환한다.
- 외부 URL과 다른 PDF를 여는 `GoToR`은 내부 참조와 구분한다. 외부 웹 링크를 지원한다면 허용된 URL 스킴과 새 탭 속성을 적용한다. PDF 스크립트나 임의 파일 실행은 연결하지 않는다.

### 좌표 이동과 복귀

- `pageTo()`와 별도로 목적지 좌표를 받는 이동 경로를 만든다. 같은 페이지의 다른 위치로도 이동할 수 있어야 한다.
- `PdfView`는 목적지 요청 식별자를 받아 페이지·줌이 바뀌지 않아도 스크롤을 실행한다. 렌더링 후 기존 위치 복원과 목적지 이동이 서로 덮어쓰지 않도록 실행 우선순위를 정한다.
- 좌표는 viewport API로 변환하고 실제 스크롤 영역·여백을 반영한다. 페이지 번호만 바꾸거나 PDF y좌표를 그대로 `scrollTop`에 넣지 않는다.
- 참조로 본문을 이동시키기 직전에 현재 DOM에서 화면 위치를 캡처한다. 복귀 기록은 `{ page, zoom, PDF 좌표 기준 화면 기준점 }`을 사용하고 가로 위치도 포함한다. 세로 비율만 저장하면 창 크기 변경 시 같은 문장으로 복귀하기 어렵다.
- 복귀 기록은 책별 세션 메모리에 제한된 스택으로 둔다. A→B→C이면 C→B→A로 복귀하고, 스크롤·줌·단순 페이지 넘김 자체는 새 참조 이력을 만들지 않는다. 복귀 후 현재 독서 위치는 기존 저장 경로로 저장한다. 새로고침·다른 기기에서 참조 이력까지 복원하는 작업은 후속 범위다.
- 이력은 목적지 검증과 렌더링 성공 후 확정한다. 실패 시 원래 위치를 유지하거나 복원하고 오류를 알린다. 연속 클릭에서 이전 비동기 결과가 최신 참조를 덮어쓰지 않게 한다.

### 미리보기 렌더링

- 문서 로딩과 페이지 표시를 분리한다. 본문과 미리보기는 같은 `PDFDocumentProxy`를 공유하되 canvas·스크롤·줌·렌더 작업은 각각 소유한다.
- 기존 `PdfView`를 그대로 두 개 만들면 문서를 각각 로딩한다. 문서를 소유하는 상위 계층과 재사용 가능한 페이지 표시 컴포넌트로 분리하는 변경이 먼저 필요하다.
- 초기에는 미리보기 한 개만 열고 대상 페이지 한 장만 렌더링한다. 다시 클릭하면 같은 창 내용을 교체한다. 미리보기 안의 중첩 링크와 여러 창 고정은 후속 범위다.
- 닫기·대상 변경·책 전환 시 렌더 작업을 취소하고 미리보기 canvas를 해제한다. 공유 문서는 소유 계층에서만 파괴한다. 본문에서 사용하는 페이지 리소스를 미리보기 닫기 과정에서 정리하지 않는다.

## 단계와 완료 기준

### 1단계: 내부 이동과 복귀

링크 표시, 목적지 해석, 같은 페이지를 포함한 좌표 이동, 여러 단계 복귀, 오류 안내를 구현한다. 이 단계에서는 클릭 시 직접 이동한다.

직접 생성한 링크 PDF를 사용해 명명/명시 목적지, 페이지 참조/정수 인덱스, 페이지 상단 이외의 목적지, 같은 페이지 링크, null 좌표, 맞춤 형식, 회전·crop·고배율을 검증한다. A→B→C 복귀 시 페이지·줌·가로세로 위치를 확인한다. 저장 실패가 복귀 기록을 깨뜨리지 않는지 확인한다.

### 2단계: 미리보기를 기본 동작으로 적용

공유 문서 기반 미리보기, 확대·스크롤, 본문 이동, 닫기·포커스 복원, 모바일 하단 시트를 구현한다.

미리보기를 조작해도 본문 페이지와 서버 독서 상태가 바뀌지 않는지, 질문이 기존 본문 문맥을 사용하는지 검증한다. 빠른 링크 교체·렌더링 중 닫기·책 전환·렌더 오류를 검증한다. 키보드 사용, 본문 텍스트 선택, 기존 AI 대화와 패널 너비 조절의 회귀를 Playwright로 확인한다.

### 후속 범위

링크가 없는 참조 문구 자동 탐지, 캡션과 하위 그림 영역 추정, OCR 링크 생성, 여러 참조 고정, 참조를 문맥으로 질문하기, 기기 간 복귀 이력 동기화는 분리한다. 특히 단순히 `Figure` 문구가 있다는 이유만으로 정확한 링크나 그림 경계를 추정하지 않는다.

- 저장소의 `PdfView.tsx`, `Reader.tsx`, `useReadingState.ts`, `api.ts`, `style.css`와 설치된 PDF.js 타입·번들을 확인했다. 실제 사용자 PDF의 링크 데이터는 열람하지 않았다.

- [PDF.js 4.10.38 AnnotationLayer 소스](https://github.com/mozilla/pdf.js/blob/v4.10.38/src/display/annotation_layer.js): 링크 주석과 링크 서비스 연동 구조.

위 설계의 적용 결과와 범위 조정은 문서 앞부분의 구현 결과를 기준으로 한다.
